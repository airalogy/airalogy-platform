# 协议评价与采用情况

Protocol Rating 在 Star 之外提供按版本的使用评价、执行反馈和可解释的推荐度。它不认证科学质量、实际物理实验、独立复现或成功率，也不依赖 AI。

## 怎么使用

在协议详情打开**评价与使用**，或点击项目协议列表、Hub 卡片的评价入口。选择准确版本，以及**我有权查看的范围**或**仅公开分享**。每次读取均根据当前可访问证据重算，因此不同用户看到的统计可能不同。原版本的直接使用与派生版本的采用分别统计。

保存 Record 后，可选择**可选：评价本次使用**；不强制弹窗，不影响继续工作。把同一次执行的多个样本记录一起选择，填写执行情况，并确认是否为实际使用。不勾选实际使用时保存为测试反馈，不计分；尚无法判断的执行也暂不计入，之后可以更正。中止、阴性结果不自动等于差评或科研失败。

当记录已有完成的 `ResearchProtocolRun` 时，沿用该执行身份；普通记录则创建最小的、可审计的使用凭据，仅描述用户确认的一组记录，不另建执行系统。现有运行对象不能可靠区分真实工作与模拟，因此两条路径都需要明确确认实际使用。历史导入、修订、预览及未归类记录不会自动计为实验次数。凭据只能说明平台内有记录和用户声明，不能证明物理实验真实发生。

**评价此版本**为每位用户、每个准确版本保留一条当前总体评分。关联有效使用凭据后成为使用者评价；创建者或通过 Airalogy 身份关联的作者／维护者自评与阅读意见单列，不影响使用均分。可用直接派生协议的执行对来源版本评价，但须说明适用条件及调整，不视为原版本未经修改的执行。

在**我的使用反馈与更正**和**我的评价修订历史**中修改或撤回；保留历史。撤回后记录仍绑定原凭据，不能通过反复创建来增加次数。并发过期修改会报冲突。协议作者不能删除他人的差评。

## 试行算法 `protocol-rating-v1-trial`

这是经过合成边界样例验证的产品规则，尚待获授权的真实试点数据校准，不是经过科学验证的质量公式。不同学科的分数不应直接比较。

1. 原始 1–5 分均值和五档分布单独显示。
2. 每个 Lab 的评价权重最多等于 5 人：将各 Lab 均值乘 `min(人数, 5)` 后相加。加入 3 条中性先验：`posterior = (加权总分 + 9) / (有效人数 + 3)`。
3. 令 `q = (posterior - 1) / 4`，评价贡献为 `90q`。
4. 使用量 `u = min(各 Lab 的 min(真实使用次数, 3) 之和, 20)`；有效跨 Lab 采用覆盖 `r = min(采用 Lab 数, 5)`。
5. 采用贡献为 `10q × (log(1+u)/log(21) + log(1+r)/log(6)) / 2`。
6. 两项相加保留一位小数。至少 **3 位有依据的非作者使用评价者**才显示数值。单实验室可满足要求，不强制要求多个 Lab。

使用量最多加 10 分，且受评价质量约束，不能淹没大量负面反馈。Lab 覆盖不再额外重复加分。专家没有倍数权重。未评价不会补零或补满分；未归类 Record 与确认使用次数并列解释。保留最近更新等发现入口，项目内可按确认使用和有效复用排序，先排序再分页，不设置跨学科综合分排行榜。

空复制只计副本，不计有效复用。有效复用需要直接派生关系及合格使用凭据，采用 Lab 和副本创建者均须区别于来源。相同创建者在同一 Lab 反复复制只计一次采用；同一 Lab 不同创建者可产生不同采用，但推荐度的复用贡献仍只计一个 Lab。不递归计算整个派生树，避免重复归因。不同 Lab ID 不证明组织独立。

**查看计算依据**显示权重、分项、分布、范围和时间。**下载计算依据**保存可复算的 JSON，包括匿名评分直方图和计数，不包含评论、评价者 ID 或 Record 链接。汇总同步重算，失败显示错误，不使用过期私有分数。写入修订审计保留当时算法和策略；重新查看历史协议版本展示该版本目前有效证据及明确标识的当前算法，不冒充过去某日的分数。引用历史分数时保留导出的依据。

## 权限

公开协议的内部反馈也默认不公开。执行反馈与总体评价分别选择公开，且来源协议、记录必须可公开读取。公开评价包含填写的文字、显示身份及评分，不包含原始记录内容和链接。公开、复制协议不会自动公开此前私有反馈；私有部署不向 Hub 上报。

API 每次检查来源权限、删除、版本、撤回和执行状态。公开统计不包含私有采用，连计数也不包含。撤权和撤回后，下次读取即移除受影响贡献。仅有自己记录阅读权的用户不能查看其他人的凭据统计。`scope=public`始终按匿名来源权限筛选。关联依据失效后仍可撤回自己的总体评价。

首期不展示未经核验的专家身份，不虚构技术校验通过。正式专家治理、领域维度、跨实例授权汇总和真实数据校准仍是 Issue #23 的后续范围。

## 接口与验证

- `GET /protocol-ratings/{protocol_id}?version=...&scope=accessible|public`：版本汇总。
- `GET/PUT /protocol-ratings/{protocol_id}/mine?version=...`：本人总体评价、修订历史；写入携带 `expected_revision`，相同重试不重复投票。
- `GET /protocol-ratings/{protocol_id}/records?version=...&page=...`：本人可用记录，按记录身份而非修订分组。
- `POST /protocol-ratings/{protocol_id}/uses?version=...`：幂等请求键、记录分组、实际／测试声明、执行反馈及范围。
- `PUT /protocol-ratings/{protocol_id}/uses/{use_id}?version=...`：本人更正、撤回，携带修订号。
- `GET /protocol-ratings/{protocol_id}/uses/{use_id}/history?version=...`：本人执行反馈审计历史。

迁移 `0083_protocol_rating`接在 `0082_external_research`之后，仅增加反馈表，不回填或改变科研数据。覆盖算法边界、增益递减、并发去重、版本、私有／公开／撤权、派生采用、科研执行身份、隔离事务内迁移往返，以及桌面／手机中英文流程。真实数据库测试纳入 `pnpm research:integration`及扩展的受影响 pre-push 检查。

显式彻底删除 Lab 时，在同一事务内清理本范围反馈与审计；其他范围的评价仍引用本 Lab 的使用依据时会阻止删除，不静默删除外部来源关系。普通软删除只影响当前贡献。
