# Airalogy Platform v0.5.0-beta.1

此版本是用于明确选择的内部试用的 beta，汇总 v0.4.1 之后的研发工作台、研究文档、组织导航和科研工具更新。它不是稳定版，也不表示任何实例已经完成升级。完整逐项变更保存在发布包的 `CHANGELOG.zh-CN.md`。

## 研发工作与导航

- 项目研发事项支持需求、任务、问题与里程碑，以及负责人、依赖、列表、看板和计划时间轴。讨论、决策、证据、测试与验收分别记录，支持版本冲突提示和本机输入恢复，无需先创建 Protocol。
- 文档承载日常记录、会议和方案，支持模板、自动保存、记录日期、资料附件及结果快照；首页可以继续最近工作。另存模板不携带实测值或附件，个人文档仍按原权限隔离。
- 组织支持公司、研究机构和实验室。单机构使用项目短链接和 `/organization`，多机构使用 `/orgs`；旧 `/labs` 浏览器链接继续兼容。此改动不重命名现有项目、不改资产 ID，也不改变访问权限。
- 单机构个人页显示实际组织归属和角色，移除重复组织数量与列表。补齐个人页、首次设置、登录、项目菜单等处的双语文案，并改善窄屏搜索与筛选。

## Protocol、Record 与科研工具

- Protocol 编辑与 Record 填写使用原生 AIMD Recorder，支持逐字段确认 Aira 修改、保留本机草稿和独立示例预览；修复 ZIP 根目录文件漏读和文档最后一次输入未及时保存的问题。
- 提供按准确版本的 Protocol 评价、可选使用反馈和权限感知的采用指标；Aira 表达偏好由用户明确保存或忘记，不自动推断习惯。
- 外部科研工具可在独立授权范围内读取不可变快照、提交私有分析报告和候选方法；写入与 Protocol 候选发布保留网页确认。已有令牌不自动扩权，历史 Record 版本保留。
- 平台提供自托管入门演示和中英文字幕，示例数据明确为虚构。涉及真实模型的 Aira 操作需单独配置服务；基础研发管理不依赖 AI。

## 版本与交付

产品版本、网页和镜像使用 `0.5.0-beta.1`，Python 包采用等价版本 `0.5.0b1`，Git Tag 为 `v0.5.0-beta.1`。预发布仍须通过准确提交的源码 CI、来源与摘要校验、产物验收、备份恢复及升级检查。GitHub Release 标为预发布，不设为 Latest，不更新稳定镜像别名。私有运维资料从 Git 和构建上下文中排除。

公开发布与部署是独立操作。安装前选择完整且验证通过的发布包，记录版本、完整 Git SHA、发布清单摘要和镜像摘要；不要由一个版本号推断实例实际运行的代码。

## 升级与验收

从正式 v0.4.1 升级会经过 `0079_research_documents` 至 `0086_project_work` 八个迁移，涉及文档、模板、访问历史、外部科研、评价、Aira 偏好、组织底座和研发事项。已有开发实例必须以实际数据库 revision 和源码为起点；已在 `0086_project_work` 的实例也需核对迁移内容和配置，不能只比较页脚版本。

1. 依照[发布与部署身份](../release-and-deployment-identity.md)核验数据库、引用文件、配置及对应产物的恢复点，并演练实际源版本到目标版本的升级。
2. 在隔离测试资产上检查登录与权限、旧链接跳转、文档保存后刷新、研发事项与讨论保存、Protocol 编辑和 Record 提交。AI 关闭时检查基础路径仍可用。
3. 安排必要的停写窗口，安装同一份通过验收的不可变产物，核对运行身份、健康状态及受影响的用户任务。
4. 明确回退条件和切换后新增写入的处理方式。更换应用镜像不会撤销数据库迁移，不自动覆盖数据库或丢弃新数据。

beta 验证通过不等同于真实仪器资格认证，也不包含 SSO、多节点高可用或法规合规认证。此说明不代替具体实例的验收和恢复记录。
