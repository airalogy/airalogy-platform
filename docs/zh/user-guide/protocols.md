# Protocol

Protocol 是可复用、可版本化的研究流程与结构化数据定义。它可以同时包含供人阅读的说明、步骤、检查项、变量、文件和其他有明确类型的输入。

## 查找或创建 Protocol

进入 Project 后，可以看到由该 Project 管理的 Protocol。根据角色和实例配置，你可以直接创建、从示例开始、导入受支持的包，或使用 AI 辅助草拟。生成或导入的内容在用于真实研究前仍需人工审核。

如果界面要求填写 Protocol ID，应使用稳定、清晰的标识。显示名称和描述可以解释科学用途；ID 会用于路由和集成，创建后未必能安全修改。

Aira 生成的 Protocol 会先校验，再交付草稿。发现确定性错误时，最多尝试一次最小化修复，并重新校验；修复失败或需要科研判断时保留原始草稿。编辑器还会在修改后及保存前检查当前 AIMD、Python、TOML 源码，显示文件名和可用的行号。点击 **让 Aira 修复** 可查看建议差异，确认后才应用；等待期间修改过的文件由冲突检查保护。

**静态检查通过** 表示 AIMD 结构、引用、计算依赖及 Python/TOML 语法检查通过，不代表科研内容、外部依赖或客户端 JavaScript 执行一定正确。正式保存仍由隔离执行器校验完整协议包。校验服务不可用会单独提示，不会误报为语法错误。关闭 AI 后仍可手工检查；修正问题或重试后再保存，校验失败会保留本地草稿。

## 不依赖 AI 和设备的入门练习

在 Project 内选择**新建协议 → 从模板开始 → 首条 Record 练习**，填写易于识别的名称，在编辑器中打开草稿并点击**保存**。确认实验室、项目与版本后再保存。创建 Protocol 需要相应权限；记录者可请 Protocol 负责人为团队准备一次。

中英文练习模板包含两个必填项、示例数值及保存、提交、修订说明。它会创建普通的可编辑、可版本化 Protocol，并非单独的演示模式。练习数据明确标记为模拟数据，请放在练习项目中，不作为科研证据。整个流程不依赖 AI 服务。

在可视化编辑区可以直接修改实验步骤和字段定义，也可以切换到源码编辑 AIMD。已发布版本以只读方式打开，需要修改时先创建草稿。

在编辑器的 **Preview（预览）** 中选择**用示例数据测试**。修改示例值后点**校验测试表单**，即可查看需要处理的字段。**退出测试**会丢弃这次试填。草稿按当前 AIMD 声明校验，已发布版本还可使用已保存的字段结构。Python 代码在平台正常执行流程中运行。

## 有意识地修改

修改已经产生 Record 的 Protocol 前：

1. 确认当前版本以及下游工作是否依赖现有字段。
2. 需要保持历史 Record 可比时，优先采用兼容的增量修改。
3. 字段改名、删除或改变类型属于 schema 变化，需要明确审核。
4. 发布或记录前预览渲染结果，并解决校验错误。

AI 可以帮助草拟或解释变更，但负责研究的人员仍应对科学正确性、安全性和最终字段定义负责。

## 计算字段：客户端还是服务端

简单、确定性的计算可以放在同一个 `protocol.aimd` 文件中：

````aimd
长度：{{var|length: float, ge=0}}
宽度：{{var|width: float, ge=0}}
面积：{{var|area: float, ge=0}}
```assigner runtime=client
assigner(
  {mode: "auto", dependent_fields: ["length", "width"], assigned_fields: ["area"]},
  function calculate_area({length, width}) { return {area: length * width}; }
);
```
````

客户端支持 `auto`、`auto_first`、`manual`。输入和输出必须是已定义字段，一个输出只能有一个计算来源，依赖不能成环。计算仅在可编辑 Record 中通过受限 AIMD JavaScript 运行时执行；输入或输出无效会报错，不保存部分结果。只读报告保留原来保存的值。

外部服务、文件、密钥、科学计算库、重型计算或权威校验应使用服务端 Python。浏览器算出的值不是安全或科研真实性保证。不要把 JavaScript 写入 `assigner.py`；Python 可以保留在普通 `assigner` 围栏或独立 `assigner.py` 中，但不要重复实现同一计算。

CSV/API 导入不会运行浏览器计算。应按下载模板提供所需派生字段；缺失或无效的必填值会被拒绝。两种运行时用于真实科研前，都需要审核公式及原始观测值。

## 复用与 Workflow

只有在流程和数据契约确实相同时，才应跨实验复用 Protocol。科学含义发生变化时，应建立独立 Protocol 或明确的新版本。

启用 Protocol Workflow 后，可以把多个 Protocol 连接为有向研究流程。执行前应检查起始 Protocol、转移关系和数据映射。Workflow 应让交接更清楚，而不是隐藏步骤之间未记录的假设。

## 分享与引用

在单机构版，打开项目或协议，点击**分享**即可查看谁能打开工作区链接。

- **仅项目成员可见**是新项目的默认值。长期合作可在**团队**中添加成员，按角色授予权限。
- 在**项目设置 → 项目可见范围**选择**组织内可见 · 需登录**，本组织成员即可阅读项目介绍和继承项目权限的协议正文。单独设定协议权限的内容、实验记录、会议和经营账仍按各自权限访问。也可以在私有项目的协议中选择某一版，单独生成组织内分享链接。
- 如需让外部合作者免登录阅读，组织所有者或管理员先在**组织管理 → 设置 → 对外分享**启用对外发布，再由有发布权限的人在项目或协议中选择**分享**。发布协议时选择版本和**对外公开 · 无需登录**，预览正文，勾选允许下载的随附材料，确认发布后复制分享链接。想公开项目介绍时需单独发布；该介绍只列出已对外发布的协议版本。

升级单机构实例时，旧版标为「公开」的项目改为组织内可见。对外分享需重新预览、发布并取得专用链接。

新版本需另行发布。可从**分享**面板撤回某个链接；关闭组织的对外发布会撤回全组织的对外链接，重新开启后需要重新发布。

接收者通过分享链接打开私有资料时，可以在提示页登录，随后返回原链接。已登录但仍无法打开时，请让分享者核对链接，并检查你的项目、协议或记录访问权限。社区版中允许匿名阅读的公开协议仍可直接打开。

角色说明见[协作](./collaboration)，使用 Protocol 采集数据见 [Record](./records)。
