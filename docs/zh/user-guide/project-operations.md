# 项目经营与经营总览

组织所有者或管理员打开「组织管理 → 设置 → 项目经营设置」，点击「启用组织经营」。选择需要核算的项目，勾选「启用此项目的经营账」，为已有项目访问权限的成员选择经营角色后保存。新安装和升级后的组织默认关闭此功能。

从项目导航进入「经营」。窄屏下可点「更多 → 经营」。组织所有者和管理员可以从此处进入「项目经营设置」，为当前项目开账或配置经营角色。普通项目成员需要取得经营角色才能查看账目。

在「项目收支」点「记一笔收支」，选择收入或支出，填写流水名称、实际日期和金额。客户来款选「客户回款」，可直接选择合同，也可选择应收期次；供应商退押金等选「其他收入」，只计入项目现金流。付款可关联已核实成本。「查看收支明细」可筛出项目的收入和支出。已有未分类收入沿用原有待匹配口径，财务可在核实用途后编辑更正。

经营页默认显示累计流入、累计流出、净流入和收支明细。有合同后会显示已签金额（含税）、已收合同款及剩余待收。点击金额可追溯参与计算的明细，展开「合同明细」可按合同查看。草稿不计入已签金额，待收按每份已签合同分别计算，最低为零。已明确归属合同但尚未核销到期次的客户款计入已收合同款，期次逾期仍按实际核销计算。

项目负责人可以从第一笔投入起申报成本、维护合同及预测。财务核实成本和实际收付，管理层可从经营总览逐项查看已获授权的项目、合同与明细。撤销某人的经营权限后，相应账目和凭证也会从其可访问范围中移除。

## 从空项目走一遍

在本地演示组织另建一个带「虚构验收」字样的私有项目，加入三个演示账号。在组织设置中启用经营，选中项目、启用项目经营并分配上表三种角色。仅获得普通项目权限的第四个成员可用于检查访问边界。

| 步骤 | 使用者和录入内容 | 保存并刷新后的期望 |
| --- | --- | --- |
| 1 | 负责人申报 10 月 30 日设备成本 6,000 元，需付 6,000 元。财务核实，在「项目收支」登记支出 4,000 元并选择该成本。 | 已核实直接成本 6,000，已付 4,000，净流入 −4,000，未付 2,000。尚未签约，毛利待估算。 |
| 2 | 负责人补合同 A，含税额 106,000，不含税收入 100,000，选择已签并填实际签章日期。将原设备成本归入 A，记录更正原因。负责人估算剩余成本 34,000；财务登记核实截至 11 月 11 日。 | 设备业务日期仍是 10 月 30 日。预计毛利 60,000。 |
| 3 | 负责人添加首期 50,000 元（11 月 10 日到期）和尾期 56,000 元（客户签回验收单后 30 天，暂不填到期日）。财务登记 11 月 9 日实收 30,000 元，先留待匹配，再编辑本笔并选择首期。 | 实收始终 30,000，合同未收从 106,000 变为 76,000，净流入 26,000。次日是否逾期按上文两个日期核对。 |
| 4 | 财务再付设备余款 2,000 并关联同笔成本。 | 已付 6,000，净流入 24,000，直接成本仍为 6,000。 |
| 5 | 负责人增补已签合同 B，含税额与不含税收入各 10,000。另申报一笔 1,000 元的项目共用成本，财务核实，暂未付款。 | 含税合同额 116,000，直接成本 7,000，预计毛利 69,000。净流入仍为 24,000。 |
| 6 | 管理层点总览中的金额，核对明细及历史。用负责人尝试登记收款、用普通成员直接打开经营页，再撤销一个经营查看角色并刷新。 | 管理层可追溯、负责人无法登记收款、普通或已撤权成员无法读取相应账目和凭证。 |

## 重现数据与测试

可复用仓库的本地浏览器测试数据库、Redis、对象存储以及开发 API 和前端，启动方法见 [E2E 环境说明](https://github.com/airalogy/platform/blob/main/tests/e2e/README.md)。在运行中的本地隔离实例上，从仓库根目录执行以下命令准备演示。脚本使用固定的本地 API 端口 4100，在 `dev_lab` 启用经营，并设置虚构项目三个演示账号的角色。重复运行相同的入账请求不会重复记账。

```bash
source tests/e2e/scripts/api-env.sh
python3 tests/e2e/scripts/seed-project-operations.py
```

`apps/api/tests/test_project_operations.py` 使用已升级的独立 PostgreSQL，校验上表六步、权限撤销、金额更正、历史版本和并发重试。`tests/e2e/specs/project-operations.spec.ts` 使用四个独立浏览器会话完成上述六步，包括普通项目成员访问、财务收款请求重试、管理层手机视口逐级追溯、撤权及历史逾期明细核对。手动再次新建一笔表示另一笔业务，测试请求重试请使用同一请求标识。
