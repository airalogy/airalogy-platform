# 项目会议与研究活动

项目「文档」默认保留独立文档，包括手工写的会议笔记。搜索标题、正文或选择会议类型时，也可找到有权查看的正式会议纪要；点击结果直接打开对应会议。会议列表可直接搜索，展开「筛选」可按参会人或起止日期缩小范围。

进入项目的“会议”板块，新建会议记录。默认记录已召开的会议，填写实际日期；具体时刻可选。补录历史会议不会因为今天录入而移到今天。会前可以先准备议题，计划时间可留空；尚未召开和已取消的会议不进入已发生的活动统计。

## 参会人员与可见范围

从项目成员中选择账户，或按姓名记录未注册人员及其单位。可以区分已参会、已邀请、未参会与待确认。参会名单不自动授权。普通会议默认项目读者可见；选择“仅指定成员可见”时，创建者保留访问，其余成员需要明确授权。授权仍受项目权限约束，不会把外部人加入项目。创建者管理参与者与权限；可查看、可评论、可编辑分别设置。可见范围适用于纪要及其历史版本。

文档列表、历史、会议列表、活动图和事项中的来源引用都重新检查会议访问权限。会议在文档中使用同一份正文与修改历史。已有附件继续遵守自身可见范围，会议授权不会把项目文件变为仅参会人可见；需要限制附件时应先按文件权限处理。首版不包含外部账户邀请或访客共享。

## 用 Aira 起草会议

AI 可用时，有会议写入权限的成员可在项目右侧打开 Aira，粘贴讨论内容，再用对话修改。提交给模型的内容仅包括这次输入的对话与草稿。点击「核对纪要与待办」，在会议表单中确认日期、可见范围、待办和负责人，再一次保存。保存前，草稿只保留在当前页面会话中。

## 纪要、补充意见与行动项

填写讨论、决定及依据、待确认问题和下一步，点击保存并核对反馈。并发修改时拒绝覆盖旧版本；保留当前输入，查看最新内容后再决定如何合并。关闭或离开页面前会提示未保存内容。意见独立追加，记录作者与时间，不会覆盖纪要。

纪要可以与多条行动项一起保存；保存后也可关联已有研发事项或批量追加。新事项按项目事项权限共享；只关联准确的会议版本，不把私有纪要正文复制到事项。没有会议权限的项目成员仍可跟进事项，但不能打开会议来源。重复提交同一个创建请求不会重复生成事项。列表显示事项当前状态；历史纪要保留当时的事实。下一次会议继续关联同一事项。

## 项目概览与活动回顾

概览的“研究活动”默认显示近 90 天热力图及近期活动。点击某天，下方切换为当天明细；清除日期回到近期活动。按会议、文档与日志、实验 Record、事项与研究进展、Protocol、知识筛选时，图和列表使用同一套权限与统计条件。进入完整活动可选择年份并分页浏览。

会议按实际发生时间归日，一场会议只算一次；修改正文和参会人不增加次数。图与明细使用当前浏览器时区，可通过日期范围旁的说明按钮查看；无权查看的内容不进入数量。活动数量用于回顾，不代表研究质量或完成度。文档、任务、Protocol、Record 沿用各自的真实保存/提交事件，普通讨论和标题修改不冒充事项进展。

周期排期、提醒、实时共同编辑、录音转写留作后续扩展。普通会议无需创建 Protocol；需要标准化执行的评审或测试可关联已有 Protocol/Record。

## 按姓名协作，再关联账号

添加参会人或行动项负责人时，可以选择项目中的账号，也可以通过“添加姓名 / 关联账号”登记项目人员。登记姓名不要求对方先注册。项目人员名单在项目内共享；如果姓名只适用于本次会议，可使用“仅在本次会议按姓名添加”，不加入共享名单。

对方注册并取得项目访问权限后，项目管理员可以把这条人员记录关联到账号。确认界面会显示受影响的负责事项数量。原有事项仍关联同一个人，随后会出现在该账号的“我的任务”中；无需逐条重新分配。关联不会邀请成员、增加权限或改写历史会议姓名。同名人员不会自动合并，误关联可以由管理员纠正，系统保留关联记录。

## 从纪要直接形成行动项

会议默认以阅读方式打开，点击“编辑”才进入编辑表单。新建会议时，可在正文后添加多项行动项并一起保存；已有会议也支持批量追加。可以逐行填写或粘贴多行标题，再补负责人、协作人、目标、验收条件、日期或时间要求。只知道“下次会议前”时填写时间要求，日期留空。

批量保存全部成功后，行动项会出现在研发事项中，并关联当时的会议版本。任一行有问题时，整批不写入，界面保留输入；重复提交不会重复创建。已有事项直接关联，避免另建一份。行动项对项目可见，请明确填写可共享的任务内容。
